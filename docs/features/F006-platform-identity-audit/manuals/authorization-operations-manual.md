# 授权体系操作手册

> 适用范围：F006 身份、权限与审计底座。本文面向平台管理员、BU 管理员和安全审计人员，说明用户、角色、权限矩阵、临时授权、审计校验的标准操作。

## 1. 授权模型总览

平台采用 **RBAC + 租户/BU 边界**：

- 用户只保存账号资料、状态和所属租户/BU。
- 功能权限、菜单权限、BU 管理能力统一挂在角色上。
- 用户通过“角色分配”获得权限；不得把 BU 权限直接挂到用户资料上。
- 自定义角色可设置父角色权限上限，避免超过岗位职责。
- 权限变更、角色变更、账号停用会使相关会话失效，用户需重新登录。
- 高危操作必须写入审计日志并可校验签名。

核心链路：

```text
User -> platform_user_role -> Role -> platform_role_permission -> Permission
```

## 2. 角色与权限说明

### 2.1 预设角色

| 角色编码 | 角色名称 | 用途 | 是否可修改权限 |
|---|---|---|---|
| `SUPER_ADMIN` | 超级管理员 | 全平台所有权限 | 否 |
| `BU_ADMIN` | BU子管理员 | BU 范围内用户、角色和基础权限管理 | 否 |
| `DATA_ANNOTATOR` | 数据标注工程师 | 标注执行 | 否 |
| `DATA_REVIEWER` | 审核工程师 | 标注审核 | 否 |
| `MODEL_TRAINER` | 模型训练工程师 | 模型训练/实验 | 否 |
| `MODEL_OPS` | 模型应用工程师 | 模型部署/推理运维 | 否 |

预设角色只允许分配给用户，不允许在页面或 API 中修改其权限。

### 2.2 自定义角色

自定义角色用于承载 BU 或项目的差异化授权。创建时建议遵循：

- 角色编码使用大写英文与下划线，例如 `CABIN_DATA_MANAGER`。
- 作用域优先选择 `BU / 租户范围`；只有超级管理员才能创建全局角色。
- 如角色从岗位模板派生，应选择“父角色权限上限”。
- 初始权限只选择岗位必需的菜单/功能权限，遵循最小权限原则。

## 3. 用户管理操作

### 3.1 新建用户

1. 进入 **用户管理 -> 用户列表**。
2. 点击 **＋ 新建用户**。
3. 填写姓名、账号、邮箱、BU、租户 ID。
4. 点击 **创建零权限用户**。

结果：

- 用户创建后默认为 `ACTIVE`。
- 默认不分配任何角色，登录后没有业务菜单。
- 管理员必须在后续“编辑用户”中显式分配角色。

### 3.2 编辑用户资料和角色

1. 在用户列表中点击目标用户的 **编辑**。
2. 修改姓名、邮箱或状态。
3. 在“角色”中选择该用户需要的角色。
4. 如需临时授权，填写“临时授权到期时间”，格式示例：`2026-06-30T18:00:00+08:00`；留空表示长期有效。
5. 点击 **保存用户与角色**。

注意：

- BU 权限跟随角色权限矩阵生效，不在用户资料中直接维护。
- ACTIVE 用户不能被撤销为零角色，除非该用户原本就是新建零权限用户。
- 最后一名超级管理员不能被停用，也不能被撤销 `SUPER_ADMIN`。
- 角色变更会写入 `ROLE_ASSIGNED` / `ROLE_REVOKED` 和 `SESSION_INVALIDATED` 审计。

### 3.3 解锁用户

1. 在用户列表点击 **解锁**。
2. 系统清空失败次数和锁定时间，并使旧会话失效。

触发场景：连续登录失败 5 次后账号锁定 30 分钟，可由管理员提前解锁。

## 4. 角色管理操作

### 4.1 新增角色

1. 进入 **用户管理 -> 角色管理**，或 **权限管理 -> 创建角色**。
2. 点击 **＋ 新增角色 / ＋ 创建角色**。
3. 填写角色编码、角色名称、描述。
4. 选择作用域：`BU / 租户范围`、`项目范围` 或 `全局范围`。
5. 可选选择“父角色权限上限”。
6. 选择初始权限。
7. 点击 **创建角色并写入权限矩阵**。

校验规则：

- 预设角色编码不可重复创建。
- 自定义角色权限不得超过父角色权限上限。
- 只有超级管理员可创建全局角色。
- 创建成功写入 `ROLE_CREATED` 审计。

### 4.2 更新自定义角色权限

1. 进入 **权限管理 -> 当前权限概览**。
2. 在“角色权限矩阵”中找到目标自定义角色列。
3. 直接勾选或取消勾选对应权限行。
4. 系统会立即保存该自定义角色的权限，并刷新矩阵。

如需一次性批量调整多个权限，也可以：

1. 在 **权限管理 -> 当前权限概览 -> 自定义角色权限维护** 中找到目标角色。
2. 点击 **编辑权限**。
3. 在“权限”多选框中批量勾选或取消。
4. 点击 **保存角色权限**。

也可以从 **用户管理 -> 角色管理** 进入，找到自定义角色卡片后点击 **编辑权限**。在 **用户管理 -> 权限矩阵** 中同样支持直接勾选自定义角色权限。

约束：

- 预设角色只读。
- 自定义角色权限变更会写入 `PERMISSION_CHANGED` 和 `SESSION_INVALIDATED`。
- 所有关联该角色的用户旧会话立即失效。

## 5. 权限矩阵查看

1. 进入 **用户管理 -> 权限矩阵** 或 **权限管理 -> 当前权限概览**。
2. 行表示权限码，列表示角色。
3. `✓` 表示角色拥有该权限，`×` 表示无权限。

权限类型：

- `menu:*`：菜单可见性。
- `platform:user:*`：用户管理操作。
- `platform:role:*`：角色创建、查询、分配。
- `platform:permission:*`：权限矩阵查询和自定义角色权限维护。
- `platform:audit:*`：审计查询、导出和校验。

## 6. 审计与复核

### 6.1 查询审计

1. 进入 **权限管理 -> 申请历史**。
2. 查看操作事件、操作人、结果、风险等级和签名前缀。
3. 后端 API 支持按 `actor`、`action`、`riskLevel`、`result`、时间范围分页查询。

### 6.2 校验审计签名

调用：

```http
POST /api/v1/platform/audit-logs/{eventId}/verify
Authorization: Bearer <token>
```

返回 `valid=true` 表示该 eventId 关联审计记录未被篡改。

### 6.3 高危操作

以下操作必须重点复核：

- 超级管理员停用/撤权失败。
- 用户停用、解锁、角色变更。
- 自定义角色创建和权限变更。
- 跨 BU 越权访问。
- 审计导出请求。

## 7. 常见问题

### Q1：为什么不能在用户上直接配置 BU 权限？

因为平台权限模型要求权限统一由角色承载。用户只分配角色，这样便于复审、审计、会话失效和最小权限治理。

### Q2：新用户为什么登录后没有菜单？

新用户默认零权限，必须由管理员显式分配角色。

### Q3：为什么预设角色不能改权限？

预设角色是平台基线能力，修改会影响全局安全边界。若 BU 需要差异化权限，请创建自定义角色。

### Q4：为什么角色变更后用户需要重新登录？

权限变更后系统会递增 `sessionVersion` 并撤销旧 session，确保权限即时生效。

## 8. 运维前置要求

- 本地后端测试/构建需使用 JDK 21+；当前验证命令使用 `JAVA_HOME=C:\java\jdk-25`。
- 生产 SSO、MFA、审计冷存储、密钥来源仍为 `TODO_CONFIRM_*`，上线前必须确认并配置。
- 禁止绕过 API 直接改库授权；紧急改库必须补审计说明和复核记录。

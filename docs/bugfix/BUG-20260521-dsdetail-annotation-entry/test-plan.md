# 测试计划：数据集详情页进入标注工作台

## 测试目标

验证 `/dsdetail` 在存在已创建标注任务时提供直接进入工作台的按钮，并确保跳转后打开的是目标任务而不是默认第一条任务。

## 测试用例

| 用例 ID | 场景 | 前置条件 | 步骤 | 预期结果 |
| --- | --- | --- | --- | --- |
| TC-01 | 数据集详情展示已有标注任务 | 数据集存在标注任务 | 打开 `/dsdetail` 并切到“标注任务/训练导出” | 表格展示“进入标注”按钮 |
| TC-02 | 从数据集详情直达标注工作台 | 同 TC-01 | 点击任务行“进入标注” | 跳转 `/annwork`，显示“标注工作台”与对应任务名称 |
| TC-03 | 工作台按 taskId 打开目标任务 | 通过 state/query 传入 taskId | 打开工作台 | 优先查询并展示指定 taskId 对应详情，而不是固定第一条任务 |
| TC-04 | 标注链路回归 | 已登录且具备标注权限 | 访问 `/ann`、`/annwork`、`/annreview` | 现有标注任务页/工作台/审核页仍可正常渲染 |

## 自动化验证

- `npm --prefix frontend run test:ci -- App.test.tsx`

## 手工验证建议

1. 打开 `http://127.0.0.1:5173/dsdetail`。
2. 切换到“标注任务/训练导出”。
3. 点击某一行“进入标注”。
4. 确认跳转后的 `/annwork` 页面显示对应标注任务和样本队列。

## 风险回归关注

- 若未来工作台支持更多筛选维度，仍需保证显式传入的 `taskId` 优先级最高。
- 如果任务已完成/已取消，是否允许进入工作台由后续产品规则决定；本次仅解决入口缺失与指定任务直达。
